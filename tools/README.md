# tools/
verify.py is the stranger's standalone Python verifier: the twin of crates/verifier.

**Bricks:** 51, 52 (NORTH-STAR.md).

Download or copy just `verify.py` into an empty folder. It contains its implementation
as readable Python source and needs no repository, sibling files or local package.
Run it there with Python 3.9 or later:

```sh
python3 -B verify.py --bundle export.json --key owner-key.hex --checkpoint retained-head.json
```

The script reads local bytes and never contacts the node or a relay. The cold export,
key and covering head are input files; the key and head must have been retained
independently. Embedded claims alone yield `UNCHECKED`. Ed25519 verification requires
PyNaCl; Nostr evidence requires coincurve; C5 owner signatures require cryptography.
These providers must already be installed in the offline Python environment. An
unavailable provider refuses with `verifier:crypto-unavailable`.

For C5 owner signatures, supply a v2 export and `--owner-key PIN.hex`, an independently
retained, uncompressed P-256 SEC1 public key encoded as lowercase hex. A ledger whose rows
need an owner approval (a consumed approval, a retirement, a floor advance, a permission
grant, a binding) is `VERIFIED` only with both, and only when every retained assertion
verifies under that key; with a v1 export, a v2 export without the pin, or rows alone the
verdict is `UNCHECKED` with the single finding `verifier:owner-signatures-unchecked`.
The need is decided from the effect: every applied change must rest on exactly one earlier
consumed approval of the same operation (else `REWRITTEN gate-reference` at the apply), and a
consume is free of the owner only when it names a well-formed use of an owner-signed grant
that is in the same ledger. A missing, null or unlinked standing reference never means "no
owner needed". Not checked: a standing grant's scope, count and revocation, and rows
(broker grants, memory permissions) whose approvals this verifier cannot yet link.

The archive's flat gate rows (a `gate.consume` or `gate.apply` whose body is not the Aura
authority wrapper) are not verifiable: the rebuilt node never writes them, so each one is
`verifier:owner-provenance` at its row and a ledger holding one is never `VERIFIED`.

The script also accepts `--key KEY --rows ROWS` with optional `--prefix OLD_ROWS`,
`--retained HEAD --presented HEAD`, and `--checkpoint HEAD`; `witness BUNDLE EVENT`
checks a detached Nostr observation, and `consistency RETAINED PRESENTED` checks
only the two supplied Merkle observations. None of these checks grants authority.

Maintain the implementation in `tools/verify/`. Regenerate the standalone source after
editing it, then check that the distributed file is current:

```sh
python3 -B tools/verify/build.py
python3 -B tools/verify/build.py --check
```

The generator removes internal imports, deduplicates standard library imports and
removes empty and comment-only lines outside strings. It compiles the result and
compares every retained statement's parsed form with the package source, including
function bodies, constants, CLI rendering and refusals. It refuses conflicting names,
unsupported imports, changed statements, missing exports or more than 1,000 lines.
`--check` compares the generated bytes with `tools/verify.py`; it executes no verifier
or vectors.

In the checkout, `python3 -B tools/verify.py`, `python3 -B tools/verify` and
`python3 -B -m tools.verify` accept the same verifier arguments. The standalone
file also exports the package's helper names for existing Python callers.

# crates/kira
- **Owns:** encrypted memory, cited recall, demotion (never deletion), memory permissions, the OpenViking adapter, and Kira 2, AUKORA's shared memory (`src/shared`): one signed, hash-chained store that every agent on the Mac reads and writes through a local service (`sovereign kira serve`, its MCP shim, token issue, rotation and revocation). For recall, the shared memory calls local model servers (a loopback `llama-server` for embeddings and rerank).
- **Never owns:** authority, or the model servers it calls; it never runs a model itself.
- **Trust boundary (shared memory, Phase M):** same-uid trust: agents running as the owner's user can read token and key files; Phase N moves keys behind a separate service uid and SO_PEERCRED.
- **May depend on:** canon, aura, nostr.
- **Bricks:** 57, 58, 59, 60, 124 (NORTH-STAR.md).
- **Storage:** SQLite note retention, authenticated encryption, demotion, cited recall, permissions and local indexing; Aura and key access use injected adapters.
- **Health:** 18 private checks and 8 corner sides; missing observers report failed, never verified.
- **Integration:** save has no per-note approval; Aura must supply its nonauthorizing append route before persistence.
- **Vectors:** `vectors/aead-v1.json` records note associated-data bytes; `vectors/permission-target-v1.json` and `vectors/backup-aad-v1.json` specify permission targets and backup chunk associated data.
- **Dependencies:** encryption uses `chacha20poly1305`; nonces and identifiers use `getrandom`; storage uses `rusqlite`; local model files use `rustix`; adapters use `serde` and `serde_json`; commitments use `sha2`; statement dedupe uses `icu_normalizer` (NFKC); transient keys use `zeroize`. `hkdf` remains reserved for future owner-root-bound wrapping or backup key derivation; Kira currently receives unwrapped keys through `MemoryKeys` and performs no HKDF derivation.
- **Signatures:** a note's signature proves which registered agent the service signed for, not authorship against the service itself; the service holds the agent keys (same-uid trust, Phase M).
- **Shared recall (Kira 2), thresholds:** with a reranker, `found` needs the best rerank score to reach `RERANK_FLOOR` (-5.5, bge-reranker-v2-m3 logits); once found, notes at or above `RERANK_KEEP` (-7.0) fill the budget. Without a reranker (and for corrections) a note counts with a keyword hit or `COSINE_FLOOR` (0.60). The floors were calibrated on a practice half of Grok's 59-question eval (set hash `hybrid::CALIBRATION_SET`) and scored once on the held-out half (epoch 1, Grok's own script: practice 0.833, held-out 0.776, all 59 questions 0.805, against 0.406 / 0.333 / 0.370 before and 0.894 / 0.928 / 0.911 for the C+CE baseline); every recall carries `judged` (by, both floors, embedder and reranker model hashes, calibration set) so a receipt says which thresholds decided it. A threshold cannot separate a false-premise question from an answerable one (the abstention items score up to 3.9): a similarity hit still is not proof, so `found` also needs the evidence rule below. Change a floor only with a new calibration set and hash.
- **Shared recall, per-author share:** no author other than the owner (or the caller's own experience lane) holds more than half of the keyword pool, the dense pool, the reranked candidates or the character budget while another author's notes wait; what that author leaves unclaimed flows back, so a lone author still fills the budget (an empty place protects no one).
- **Shared memory, minting credentials:** `sovereign kira register NAME` and `sovereign kira token NAME [--rotate]` need `--owner-token-file PATH` (a mode 0600 file holding the owner's token) as soon as the store has an owner; without it they refuse `kira:owner-token-required`, with a token that is not the live owner's `kira:owner-token-refused`. The first `register NAME --owner` on a store with no owner needs no file. This is a gate against casual minting, not isolation: any process of the same user that can read the owner's token file still passes (same-uid trust; separate uids and SO_PEERCRED are Phase N).
- **Shared memory, statement dedupe:** `statement_hash` applies NFKC, lowercase, NFKC and whitespace collapse, so NFC and NFD spellings, width variants and ligatures are one statement; accents are not stripped ("café" and "cafe" stay two). Notes written before this change keep their stored side-column hash, which dedupe does not read (it recomputes from the signed text).
- **Shared recall, evidence rule (2026-10-18):** a factual `found` needs the best relevant note to stand on the owner's words (`owner-typed` / `owner-signed` capture), an owner review, an owner-run archive import (`hybrid::IMPORT_IS_EVIDENCE`, true), or ancestry roots written by at least two different authors (never web-derived). Otherwise the status is `undetermined`, reason `similar-note-unverified`, and the notes are still returned, each labelled `evidence`: `owner-review`, `owner-words`, `archive-import`, `corroborated` or `unverified`. Identical unsourced statements (same scope, privacy, epoch) share the earliest note as their one root, shown as `repeated_by`, never as support; a note that cites nothing carries `lineage: unsupported`. The derived `ancestry` table of an older store is upgraded on open (no event is rewritten).
- **Shared recall, corrections and history:** a superseded note is shown only after the live items and only when the note that replaced it (`current_id`, followed through later corrections, shown only if the caller may read it) is among them; `get` on a supersede event id resolves to that note. The latest correction in force wins. A supersede by anyone but the note's author or the owner is a proposal (it needs the proposer's own replacement note, is listed as `proposals` on the note) until the author or the owner signs `accept_correction` (event kind 4503). Notes carry `validity` (`expired` and `not-yet-valid` notes are history, never live), `state` (`proposed`, `supported`, `disputed`, `corrected`, `resolved`; a label, never a veto on `found`), and web-derived notes are left out of recall unless `include_web` is asked for. A recall group carries the lowest-trust capture of its copies.
- **Shared memory, read boundaries:** `total`/`indexed`, `list_recent` pages and cursors cover only notes the caller may read; an agent reads its own `local` notes; `resume:<name>` is read by that agent and the owner only; citing, superseding or proposing against a note the caller cannot read is refused as if it did not exist. `sovereign kira revoke` and `import` need `--owner-token-file` like minting. Every slot write must carry `expected_head` (the head the writer read, or `none`): without it the write is refused (`kira:expected-head-required`), and a newer head refuses it as `kira:resume-stale`; a head the caller cannot read counts as no head and no head id is ever returned.
